## Beginner explanation and terms

Text is a sequence of characters. Grammar specifies which sequences are allowed. Parsing interprets
permitted text as a value. Range is the set of values the receiving type can represent. Full
consumption means every input character has been checked, including any suffix or invisible byte.
These are separate questions: could an integer be read, was all input used, and does it meet our model?

Our whole-year count is n = 0, 1, 2, ... up to the largest representable int. It is measured in whole
model years. It is neither a date nor an annual interest rate. A blank entry does not mean zero.
The model allows zero years; an explicit zero carries information that missing input does not.

## The chosen contract

Accept one or more ASCII digits 0 through 9, interpreted in decimal, with value at most
std::numeric_limits<int>::max(). Allow leading zeros. Reject signs, whitespace anywhere, decimal
points, exponent notation, separators, suffixes, embedded NUL bytes and non-ASCII digit encodings.
No trimming, rounding or fractional truncation is allowed. Every byte in the supplied range counts.

These are project choices. No normalization keeps the first parser explicit. There is no additional
text-length limit; future external-input protection must address memory and transport limits.

| Example text | Hand decision | Why |
|---|---|---|
| 0 | Accept as 0 | Zero is a valid whole count |
| 002 | Accept as 2 | Leading zeros, decimal interpretation |
| Empty text | Reject | No number supplied |
| 2.5 or 2.0 | Reject | A decimal point is outside the grammar |
| -1, -0 or +2 | Reject | All signs are forbidden |
| Space then 2, or 2 then space | Reject | No whitespace trimming |
| 2x or 2e0 | Reject | Unconsumed or non-digit text |

The table records requirements. It is not evidence that a whole-year parser has passed these cases.

## Mathematics and a worked example

For digits d1 through dk, start n0 = 0. Append each digit with nj = 10 * n(j-1) + dj.
For 002 the successive values are 0, 0, 2. Leading zeros therefore change the spelling, not the value.
The recurrence describes exact mathematical meaning. A C++ implementation must check bounds before
an operation can overflow, or use a checked library conversion. Overflow is not a valid rejection test.

The local type probe reports int maximum M = 2147483647. The decimal string for M is allowed;
the string for M + 1 = 2147483648 is not representable here. Python integer arithmetic checks the
successor without overflowing a C++ int. The contract queries M on each compilation target and does
not assume every target has the same int width. A string of many zeros still represents zero.

If accepted text 002 supplies n = 2, the existing financial model is B = P * (1 + r)^n. With P = 1000
currency units and effective annual rate r = 0.05, year one adds 50 to reach 1050. Year two adds
52.50 to reach 1102.50. Decimal arithmetic independently reproduces these two interest credits.
Text 2.5 cannot be silently substituted into that two-year calculation.

## A small C++ library experiment

The fixed conversion_contract.cpp example observes two calls to std::from_chars. It does not expose
external input or implement the contract. Before running, the expected output specifies these facts:

| Fixed input | Conversion succeeds | Uses all input | Returned integer |
|---|---|---|---|
| 2x | true | false | 2 |
| -1 | true | true | -1 |

The first case proves why an error-code check alone misses trailing text. The second proves why
complete conversion alone does not impose our nonnegative digit-only policy. Neither should reach
the savings function. In particular, checking only a nonnegative result would not enforce the ban
on a signed zero spelling; the original characters matter.

## Introduce the syntax before reading the source

The charconv header supplies conversion, string supplies text, iostream supplies printing, and
system_error supplies error codes. std::string holds the original characters. const keeps each
fixed string unchanged. int suffix_value = 0 initializes the receiving integer. auto lets the
compiler infer the result type from the expression on the right.

Read the first block in order: store 2x; initialize a receiving integer; call from_chars on the
range from data() to data() + size(); print the error comparison, stopping-position comparison
and integer. data() identifies the first character and size() counts the input characters. The
end position is just after the last character. The library writes through its integer reference
parameter and returns a result containing an error code ec and stopping position ptr.

The expression ec == std::errc{} asks whether conversion succeeded; ptr == end asks whether it
used the entire range. Equality produces a Boolean, and boolalpha prints true or false. The
second block repeats the same sequence for -1. The final line states the contract consequence.
The project worksheet explains this source in order; the next session introduces parser branches.

## Assumptions, costs and failure cases

Savings assumes a constant effective annual rate, reinvestment and no cash flows, fees, tax or
inflation. Costs reduce wealth; none is estimated. Parsing cannot validate economic assumptions.
There are no trades, empirical returns or investment recommendations here.

An accepted count can still overflow the positive-rate savings calculation; C002 retains separate
overflow checks. Rejecting 2.0 is deliberate syntax policy. Leading zeros do not imply octal.
Embedded NUL rejection requires an interface that preserves input length rather than truncating.

The probe is not a parser, portability proof or security audit. The future function must reject
invalid input without a usable year value; its error API is next session. Tests do not prove mastery.

prefix, and a fully consumed signed integer can still violate a whole-year text policy. I would
preserve the original text, define the permitted grammar, check the whole range and reject values
that cannot fit. Only an accepted integer would reach the savings function, which still checks
its own financial inputs and numerical result. Today establishes that contract, not the final parser.

## Suggested answers

1. Conversion stopped at x. The numeric prefix was readable, but the full input was not accepted.
The stop position must be checked, alongside the error result and the grammar.

2. The minus sign violates the digit-only rule and -1 is outside the nonnegative model. The -0
spelling is also forbidden even if a numeric conversion would produce zero. Inspect the text.

3. Only 002 is accepted, as 2. Empty text has no digits; 2.0 contains a forbidden point; the
leading space is rejected because this contract does not trim whitespace.

4. Text above the target int maximum cannot become a valid receiving integer. A representable
count can nevertheless cause the savings calculation to overflow at a positive interest rate.
These are separate validation boundaries, and a passing parser does not guarantee a valid balance.

5. Starting at zero, the appended digits yield 0, 0 and 2. Interest is 50 then 52.50, giving
1050 then 1102.50. These are synthetic model years under fixed-rate, no-cost assumptions.
