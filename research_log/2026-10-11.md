## Beginner explanation and terms

Source is the human-readable C++ program. A compiler produces an executable. Re-running an old
executable checks that file; rebuilding checks whether today's source can produce working behaviour.
A fixture is a fixed input or expected output. Reproduction repeats a documented method and compares
observations with the recorded expectations. It does not make those expectations automatically right.

Our parser accepts nonempty ASCII decimal digits representing zero through the target int maximum.
Leading zeros are allowed. Spelling is checked before range. Invalid text returns no years; it must
not silently become zero. Zero itself is a valid horizon and returns the original principal.

## Mathematics and hand prediction

With principal P = 1000 money units and effective annual rate r = 0.05, B(n) = P * (1+r)^n for
nonnegative whole model years n. Work it out before looking at the executable: first interest is
1000 * 0.05 = 50, so B(1) = 1050. Next interest is 1050 * 0.05 = 52.50, so B(2) = 1102.50.
At n = 0, no interest period occurs and B(0) = 1000. Rejection is not B(0); it means no calculation.

| Complete text | Prediction | Reason |
|---|---|---|
| 002 | 2 years; 1102.50 | Leading zeros preserve value |
| 0 | 0 years; 1000.00 | Valid lower boundary |
| 2.5 | Reject; no balance | Dot violates digit-only spelling |
| 2.0 | Reject; no balance | Numerical wholeness does not change grammar |

## Trace the existing C++ flow

1. parse_whole_years(text) receives the original string. The const reference lets the function
inspect that string without making a copy or changing it. No floating conversion happens first.

2. The empty check and character loop enforce spelling. Each character must be between '0' and '9'.
The dot in 2.5 fails here, before an integer or financial balance can be returned.

3. std::from_chars performs checked decimal conversion. Its error code and end position are checked;
a digit-only value beyond the int maximum raises a range error. The spelling rule has already passed.

4. Only a returned integer enters compound_balance. An invalid_argument catch in the demonstration
prints rejection and returns from that case. It does not supply a substitute zero to the calculation.

## Reproduction protocol and implementation

All inputs are existing synthetic fixtures; there is no historical period, fitting or market data.
The reproduce_years_evidence.py recipe creates an empty temporary directory, compiles six executables with
C++17 and warnings as errors, runs each evidence path twice, and removes the temporary binaries.
It uses unchanged published C++ sources. No new language or strategy feature is introduced.

The six executables are savings tests, parser tests, the parser/savings demonstration, the byte probe,
and correct/wrong fractional examples. The probe is passed to the existing Python boundary oracle.
Checks compare exact stdout bytes, stderr bytes and exit status; compilation errors or timeouts fail
the recipe. The wrong example must exit 1 with three mismatches. Arbitrary nonzero failure is not enough.

The recipe also recomputes interest with Python Decimal and records source hashes, compiler identity
and the published baseline commit. It is a local verification aid, not a new production interface.
This is a fresh build in the same installed environment, not an independently provisioned machine.

## Costs, assumptions and failure cases

The savings model assumes fixed annual rate, reinvestment and no interim cash flows. Fees, taxes and
inflation are omitted and can reduce real wealth. No spread, turnover, market return or financial loss
is estimated here. Fractional-year accrual needs its own convention; casting is not that convention.

A stale binary, changed fixture or broken expected-error check can undermine reproduction. This recipe
avoids existing build outputs, compares archived bytes and checks the intended failure status. Still,
a shared faulty contract can make multiple methods agree. Finite tests cannot prove all-input safety.
No length cap, external CLI hardening, cross-platform guarantee or personal mastery is established.

## Check your understanding

1. Why does rebuilding add evidence beyond running an existing executable again?

2. Why is rejecting 2.5 different from calculating a zero-year balance?

3. Why must the wrong-adapter check inspect output as well as a nonzero exit status?

4. What does matching an archived fixture still fail to prove?

## Suggested answers

1. It checks that the available source and compiler can produce the tested behaviour. An old binary
could have come from different source. A fresh local build still shares the installed environment.

2. Rejection yields no horizon and no balance. Zero is a valid horizon with balance 1000 here.
Replacing an error with zero silently answers a different question.

3. A crash or unrelated failure could also return nonzero. Three exact mismatch diagnostics and
exit 1 establish that this deliberate fault was detected for the intended reason.

4. It does not prove the fixture or contract is correct, cover every input, demonstrate another
platform works, establish realistic investment results, or confirm Sidiq's personal understanding.
