## Beginner explanation and terms

A parser turns text into a value under a stated contract. A branch chooses what happens when a
condition is true. An exception reports failure instead of returning a normal value. A caller is the
code using the function. Our caller gets a nonnegative int or an exception, never an error disguised
as zero. Zero is a valid count, so returning zero for missing input would confuse two different states.

The contract accepts one or more ASCII decimal digits with value at most the target int maximum.
Leading zeros are allowed. Empty text, signs, whitespace, decimal points, suffixes, embedded NUL and
non-ASCII digit encodings fail. We inspect the complete string length. No trimming or rounding occurs.
Spelling errors raise std::invalid_argument; digit-only overflow raises std::out_of_range.
If an enormous number also has a suffix, spelling fails first. Error wording is not a stable API promise.

## Read the small function in order

Source: cpp/projects/savings_growth/years.cpp, with its declaration in years.hpp. The header's
include guard prevents duplicate declarations. string provides text, charconv provides conversion,
stdexcept provides exceptions, and system_error names conversion error codes. These are standard
library facilities; no dependency is added. The following explanation follows each executable line.

1. int parse_whole_years(const std::string& text) declares an integer result and a read-only reference
to the caller's string. The ampersand avoids copying that string; const prevents modification through
this parameter. The caller's string stays alive during the call, and the function retains no reference.

2. if (text.empty()) tests whether there are no characters. The braces group its branch. throw
std::invalid_argument(...) stops normal execution; the final return is not reached for empty text.

3. for (const char character : text) visits every character, including an embedded NUL. This is a
range-based loop, not a vector. Each iteration names one character without changing the string.

4. The inner if asks whether character is below '0' or above '9'. Single quotes denote characters;
the logical OR operator means either condition is enough. A forbidden character throws immediately.
This rejects -0 as spelling, even though a generic signed conversion might produce numeric zero.

5. int years = 0 initializes local storage. Initialization is not a fallback result: subsequent checks
must succeed before this value can leave the function. Failure never returns the initialized zero.

6. const char* end stores the position just after the input, calculated with data() + size(). A pointer
identifies a position in the string; this one is a boundary, not a character to read. The earlier empty
check ensures conversion is applied only after at least one digit has been found.

7. const auto result = std::from_chars(text.data(), end, years, 10) attempts base-ten conversion.
auto asks the compiler to infer the result type. The library writes through its years argument and
returns an error code ec and stopping pointer ptr. No floating-point intermediate is used.

8. If ec equals std::errc::result_out_of_range, throw std::out_of_range. This handles an otherwise
valid spelling that cannot fit the receiving int. There is no unsafe INT_MAX + 1 computation.

9. The next if rejects any other conversion error or a stopping pointer unequal to end. The explicit
complete-consumption check documents the return condition even though the preceding digit scan has
already ruled out suffixes. With conforming conversion it is a defensive check, not a separate
observed failure path. We do not claim branch coverage for it.

10. return years is reached only after all checks pass. The function prints nothing, so the same
implementation serves the fixed demonstration and tests. It leaves financial validation to C002.

## Catching failure at the caller

In parse_years_demo.cpp, a try block attempts the fixed fractional input. A matching catch handles
invalid_argument and prints rejection. If parsing unexpectedly returns, the demo exits with failure.
The separate test harness catches the required exception type; a missing or wrong exception fails
the run. It uses exit status instead of assert, so disabling assertions cannot disable these checks.

## Suggested answers

1. Empty text supplies no count; 0 explicitly requests zero years. Returning the same ordinary value
for both would hide missing input. Throwing keeps failure separate from a valid result.

2. Every character of 002 is a digit; decimal conversion succeeds and consumes the whole range;
return years gives 2. The dot in 2.5 triggers invalid_argument during the scan, before conversion.

3. A library's numeric grammar differs from our model's policy. A sign or readable numeric prefix
must not become acceptable merely because a number can be extracted. Checking bytes enforces spelling.

4. Conversion reports result_out_of_range and the wrapper throws out_of_range. A representable count
can still overflow a positive-rate balance; the financial function keeps its own validation.

5. It is a read-only reference to an existing string, avoiding a copy. An embedded NUL is a byte
inside that string, not its end. Explicit-length construction preserves bytes that a C-string
constructor would discard after the first NUL; the parser checks only the input it actually receives.
