# Text is evidence: keep it before conversion

## Research question and hypothesis

Can a whole-year savings function discover that its integer argument originally came from a
fractional value? Hypothesis: once 2.5 has been converted to the integer 2, the function has lost
the evidence needed to reject the original request. Validation must examine the original input.

C002 already calculates annual compound growth and rejects negative year counts. Its September 30
note identified conversion before the function call as a limitation. Today's curriculum slot studies
that one prerequisite. The bounded improvement is a compiled, reproducible teaching counterexample
with a hand classification worksheet. The years parser remains a later step in this week's slice.

## Beginner explanation and vocabulary

Imagine a form with a box labelled whole years. The written marks are text. Before doing arithmetic,
we must decide whether all those marks describe an allowed count. Throwing away a decimal part or
ignoring an unexplained letter changes the request rather than checking it.

**Text:** a sequence of characters, such as quoted "2.5". **Value:** a number used in arithmetic.
**int:** C++'s signed integer type; it has a finite range and stores no fractional part.
**double:** a floating-point type that can represent fractions, with limited precision and range.
**Parsing:** interpreting text as a value. **Validation:** checking the interpretation against the
model's rules. **Conversion:** changing a value's type. These are different jobs.

**Principal P:** opening money in arbitrary currency units. **Annual rate r:** effective interest
per model year, written as a fraction; 0.05 means 5%. **Years n:** a nonnegative whole count.
**Balance B:** closing money. These are model years, not dates or a market calendar.

## Mathematics and a worked example

For whole n under fixed annual compounding, B=P*(1+r)^n. Start with P=1000 and r=0.05.
After one year, interest is 1000*0.05=50 and balance is 1050. After the second year, interest is
1050*0.05=52.50 and balance is 1102.50. The two-year interest total is 102.50 units.

Now start with the numeric value 2.5. Converting it to int produces 2 in this example. C002 receives
2 and returns 1102.50. That answer is mathematically correct for two years. It is not a validated
answer to the original fractional-year request. A whole-year contract does not choose a partial-year
interest convention; do not silently introduce one by extending the exponent or discarding a fraction.

## Introduce the C++ syntax before using it

std::string is the standard text type, supplied by the string header. A quoted literal supplies its
characters. const prevents reassignment of the named variable. A semicolon ends a statement.
static_cast<int>(value) explicitly requests conversion of a numeric value to int. The cast does not
check our whole-year policy. Only the safe, fixed value 2.5 is converted in this demonstration.

Read the three declarations in text_vs_years.cpp in order:

1. `const std::string original_text = "2.5";` retains the original characters.

2. `const double fractional_years = 2.5;` separately creates the numeric value. This line does not
parse the string above it; the two literals are deliberately written independently.

3. `const int converted_years = static_cast<int>(fractional_years);` discards the fraction, leaving 2.

The existing int main() entry point and braces enclose the demonstration. The includes provide the
savings declaration, formatting, output and text facilities. The first three std::cout statements
print the text, separate number and converted integer. Each << sends another piece to the stream;
\n ends the output line. The formatting statement uses two decimal places, as in the existing demo.

The next statement calls compound_balance(1000.0, 0.05, converted_years) and prints its balance.
The last line prints the explanation of what was lost. Reaching the end of main reports success.
The project worksheet walks through the same short source; no branches or parser APIs are introduced.

## Assumptions, costs and failure cases

Assume fixed effective annual interest, no external deposits or withdrawals and no fees, tax or
inflation. Costs would reduce wealth; the model does not estimate them. There is no observed market
return, trade, statistical sample, parameter search or profitability claim. These invented numbers
illustrate a type boundary. Currency amounts printed to two decimals do not establish exact-money arithmetic.

A correct function can still answer the wrong question when its caller has changed the input.
For this interface, a negative count is rejected but a lost fraction cannot be recovered. Blank and
trailing-text cases remain hand expectations until a parser implements them. Arbitrary floating-to-int
conversion is unsafe as a range check; out-of-range conversion can have undefined behaviour.

## Interview explanation and limitations

A concise explanation: the function sees only the integer it receives. If a caller first converts
2.5 to 2, a nonnegative check cannot distinguish that value from an honestly supplied 2. Preserve and
validate the original text before constructing the integer. Then apply the financial model's rules.

## Suggested answers

1. The quoted form supplies characters stored as text. The unquoted form supplies a double numeric
value. Today's example writes them separately; it performs no text parsing.

2. The negative integer is still visible to the function. The fraction has already been discarded
before the call, so the received 2 contains no evidence of its earlier value.

3. Only "2" is accepted in this set. The others are fractional, negative, missing or contain an
unexplained suffix. These are hand decisions, not automated parser results. Blank is not zero.

4. First interest is 50, giving 1050. Second interest is 52.50, giving 1102.50. That answers two whole
years only. A fractional-year request is outside the stated contract and must not silently become two.
